# SECURITY — 프로젝트 보안 기준

> 이 프로젝트의 구조적 보안 기준을 기록한다.
> 자동 검사는 `scripts/check_secrets.py`, `scripts/check_forbidden_patterns.py` 가 담당한다.
> 이 문서는 검사 대상과 예외의 근거가 된다. 예외는 `.ai-standard.yml` 의 `allow_exceptions` 에 기록한다.

- 최종 업데이트: (YYYY-MM-DD)
- 상세 표준: `docs/SECURITY_STANDARD.md`

## 1. 시크릿 취급

- 시크릿을 코드, 로그, Git, 테스트 결과, 빌드에 넣지 않는다.
- 시크릿 파일 패턴: (예: `.env`, `*.pem`, `*.key`, `id_rsa`) — preflight 가 Git 추적을 감시한다.
- 보안 저장 실패 시 평문 저장으로 우회하지 않는다.
- 로그와 오류 보고에서 토큰, 키, 쿠키, 비밀번호를 마스킹한다.
- 실제 시크릿은 로컬 시크릿 저장소(OS 키체인 등) 또는 환경변수로 관리한다.

## 2. 기본 금지 패턴

(프로젝트에 해당하는 것만 남긴다)

```text
- shell=True
- eval( / exec(
- verify=False (TLS 검증 끄기)
- 0.0.0.0 바인딩 (로컬 서버는 127.0.0.1)
- 빈 except 또는 예외 무조건 삼키기
- 하드코딩된 관리자 권한
- 개발용 인증 우회
- 사용자 입력 기반 subprocess
- 임의 URL 프록시
- 평문 비밀정보 fallback
```

## 3. 경계 통제

- 외부 입력, API 응답, 파일 경로, URL, 원격 설정을 검증한다.
- 파일, URL, API 경로, 실행 프로그램은 허용 목록을 우선한다.
- 외부 요청은 공통 Transport 또는 Gateway 에서 처리한다.
- 로컬 서버는 기본적으로 127.0.0.1 에만 바인딩한다.
- TLS 검증을 끄지 않는다. 무한 재시도를 하지 않는다.

## 4. 권한 판정

- UI 버튼 숨김을 권한 검증으로 인정하지 않는다.
- 관리자, 유료 등급, 결제 상태를 로컬 Boolean 만으로 신뢰하지 않는다.
- 민감 작업은 백엔드와 공통 권한 계층에서 다시 검증한다.

## 5. 허용 예외 기록

자동 검사에서 예외가 필요하면 다음 정보를 갖춰야 한다.

```text
- 정확한 파일 또는 범위
- 허용 이유
- 만료 또는 재검토 조건
- 관련 ADR 또는 문서
```

|---|---|---|---|---|

## 6. 제외 대상 (프로젝트에서 요구하지 않음)

- 유료 코드 서명 인증서, HSM, TPM 필수, 강한 DRM
- 안티디버깅, 패커, 과도한 난독화
- 백신 기능, 프로세스 감시, 하드웨어 지문 수집, 상용 보안 솔루션

필요한 프로젝트가 별도로 선택한다.
