## 5. 대표 장애 시나리오와 대응

오류 코드 체계는 `docs/ERROR_STANDARD.md` 와 `templates/ERROR_CATALOG.md` 를 따른다.
시나리오마다 관련 오류 코드를 연결한다.

```text
### 시나리오: <증상>

- 관련 오류 코드: (예: APP-STORAGE-WRITE-500)
- 확인 순서:
  1.
  2.
  3.
- 조치:
- 조치 후 확인:
- 에스컬레이션 조건: (아래 §7 참고)
```

### 예시 — 시작 직후 종료됨

- 관련 오류 코드: (해당 프로젝트의 부팅 실패 코드)
- 확인 순서:
  1. 최근 로그 마지막 N줄 확인
  2. 설정 파일 존재·문법 확인
  3. 포트/파일 잠금 충돌 확인
- 조치: 설정 복구 또는 포트 해제 후 재시작
- 조치 후 확인: 헬스 체크 통과, 로그에 오류 재발 없음
- 에스컬레이션 조건: 재시작 3회 이상 동일 오류 반복

## 6. 롤백 절차

`docs/ROLLBACK_STANDARD.md` 원칙(코드/데이터 롤백 분리, 직전 정상본 보존,
무한 재시도 금지)을 따른다.

### 6.1 코드 롤백

```text
1. 직전 정상 실행파일/설치파일 확인 (rollback_point)
2. 현재 버전 중지
3. 직전 정상 버전으로 교체
4. 재시작 및 헬스 체크
5. templates/DEPLOY_LOG.md 에 롤백 사실 기록
```

### 6.2 데이터 롤백

```text
1. 마이그레이션 전 백업 위치 확인
2. 복원 절차 실행 (사전에 복원 테스트를 거친 절차만 사용)
3. 데이터 정합성 확인
4. 코드 버전과 데이터 스키마 버전의 호환 여부 재확인
5. templates/DEPLOY_LOG.md 에 롤백 사실 기록
```

코드만 되돌리고 데이터는 그대로 두는 것이 안전한지, 데이터도 함께 되돌려야
하는지는 마이그레이션 내용에 따라 다르다 — 임의로 판단하지 말고 스키마
변경 이력을 확인한 뒤 진행한다.
